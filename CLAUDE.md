# CLAUDE.md

The `mb` CLI the Metabase RDE desktop app bundles, and the `@metabase/client` package it is built on. TypeScript ESM. citty + native `fetch` + Zod + @clack/prompts. oxlint + oxfmt. vitest. tsdown.

This file is rules only. Architecture and rationale live in `docs/architecture.md`; workflows live in the skills under `.claude/skills/`.

## Types

- No `as` casts (`as X`, `as unknown as X`, `as never`, `as any`). Use type guards or Zod `.parse` at boundaries. `as const` is fine.
- No `any`. No `Record<string, unknown>` for API responses — every cross-network value gets a named Zod schema in the client's `domain/`, parsed at the boundary. Sole exemption: `packages/cli/src/output/projection.ts`.
- No `!` non-null assertions. Restructure with a helper returning a named result-or-`null` interface, as `packages/cli/src/core/auth-broker.ts` does with `readBrokerTarget`.
- No inline object types in unions, returns, or params. Name them via `interface` or `type`.
- Derive types from values (`typeof X`, mapped types over `keyof typeof X`, citty's `ParsedArgs<typeof cmd.args>`). A hand-written interface mirroring a value's shape drifts silently.
- Type guards must check the property that distinguishes what they narrow, not a weaker shared one.

## Code

- No file extensions in imports (`./foo`, not `./foo.ts`). `import type` for type-only imports.
- No comments unless the WHY is non-obvious. Never WHAT, never task/PR/path refs. This applies to prose docs too — describe the end state, never the change to it. Delete on sight: "now", "no longer", "previously", "used to", "the new …", "moved to", "renamed".
- Fail fast at boundaries. JSON parsing, file reads, HTTP responses throw or return a typed error on malformed input. Empty `catch {}` is forbidden.
- No placeholder fallbacks for absent state. `?? ""` / `?? 0` / `?? []` / `?? {}` to satisfy a type when the semantic is "missing" hides bugs — model absence with `null` or a discriminated union.
- No magic literals. Recurring constants (byte caps, timeouts, exit codes, file modes) get a named constant colocated with the canonical user.
- No boolean traps. 2+ boolean params becomes a named-options object or two functions.
- No big inline expressions. Split into semantically-named locals; flatten ternary chains with early returns or a lookup.
- Prefer the simplest realistic expression. No ceremony — repeated `override readonly`, generic gymnastics, intermediate abstract classes — where a plain field or early return is clearer.
- When a new helper subsumes an older narrower one, delete the older one in the same change.
- An `export` in `packages/cli` needs an importer outside its own file; a `*.test.ts` importer counts. The CLI ships as a bundled binary with no `exports`/`main`/`types`, so a symbol nothing imports is exported for nobody. `packages/client` is exempt — its `exports` map makes any named module public surface.
- Never fake green. No `oxlint-disable`, no `@ts-expect-error`, no `.skip`/`.todo` on a test that used to run, no weakening an assertion to match wrong output, no silently narrowing scope. If it can't pass honestly, stop and report the blocker.

## Layout

| Path               | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/client`  | Private Metabase API client: Zod `domain/` schemas, `resources/` methods, `http/` boundary, OAuth, `version/` (server profile, feature rules, method requirements)                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `packages/cli`     | The app-bundled `@metabase/rde-cli`, private, never published: `commands/` (shell only), `core/` (pure logic), `output/` (presentation), `runtime/` (platform glue)                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `packages/desktop` | Electron app (`@metabase/rde-desktop`): `contracts/` (zod IPC, settings, connection, provider, session and event schemas, plus the shared projector), `main/` (window and lifecycle, `settings/`, `auth/` with the token broker, `providers/`, `sessions/`, `git/`, `process/`, `repository/`, `cli/` with the bundled `mb`'s location and runner, `metabase/` with the panel and the sync), `preload/` (the `window.rde` bridge), `renderer/` (React, tokens, components), `scripts/` (headless drivers, `scenarios/` and the release smoke), `electron-builder.yml` (the installers, with the CLI under `resources/rde-cli/`) |
| `tests/e2e`        | Built-binary tier against a live Metabase                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

- Nothing in `packages/client` may import from `packages/cli`, touch `process`, or mutate process-global state. Its dependency budget is `zod` (peer) + `node:` builtins.
- Within `packages/client`, only `client.ts` and `resources/` may import from `resources/`. The CLI may `import type` from the resource subpaths the `exports` map publishes.
- `JSON.parse` only in `json.ts`. `fetch` only in `http/` (plus `packages/cli/src/core/auth-broker.ts`, which talks to the app's credential broker, not to Metabase). `new URL(` only in `url.ts` and `http/`. Within `packages/client`, a `setTimeout` wait loop only in `poll.ts` and `http/retry.ts`; in `packages/cli`, a hand-rolled one nowhere — wait on `node:timers/promises`.
- `process.exit` only in the CLI entry; `process.stdout.write` only in `output/`; `child_process` only in `runtime/process.ts`. `src/output/` must not import the HTTP layer — reach for `@metabase/client/errors`.
- TLS trust is the host application's to configure, so `node:tls` appears nowhere in `packages/client`; the CLI opts in for itself via `core/system-ca.ts`.
- Every `MB_` env var name is a const in `packages/cli/src/core/env.ts` and is read through `readEnv`, never raw `process.env[...]`. `MB_URL` / `MB_API_KEY` are read in `core/config.ts` only, `MB_AUTH_BROKER` / `MB_AUTH_BROKER_TOKEN` in `core/auth-broker.ts` only.
- The credential comes from the environment and nothing else, in `resolveConfig`'s order: the app's broker, then `MB_URL` + `MB_API_KEY`, then a `ConfigError`. No profiles, no keyring, no config directory, no `--url` / `--api-key` flags, no login command, no parallel client getter.
- Content is files in the user's repository. No command creates, updates, archives or deletes a card, dashboard, document, collection, segment, measure, snippet, transform, tag, job or Python library; `validate` checks the files and `git-sync import` puts a branch into Metabase. `commands/surface.ts` is the whole leaf surface and `surface.test.ts` holds `help --json` and the README table to it.
- A directory earns subfolders at ~8–10 files **and** 2+ concern-clusters. Single-role directories (`domain/`, `commands/<noun>/`) stay flat at any size. Never create a folder for one file.
- Never add: a catch-all module or bucket directory (`api.ts`, `schemas.ts`, `lib/`, `_shared/`, `_utils/`, `common/`, `misc/`); a third-party HTTP library; a dotenv parser (use `--env-file`); a color library; a dependency for a one-off helper.

## Desktop

Every rule above applies to `packages/desktop` in full.

- `src/architecture.test.ts` is where the rules below are enforced. A new one that a grep can see belongs there, not only in this file.
- The projects the app's design and code were drawn from are never named in the repository: not in code, a comment, a doc, a test, a file name, a commit message or a branch name. `src/architecture.test.ts` holds their names as a pattern spelled so it cannot match itself, and fails on any file git lists, tracked or untracked, whose path or content matches, save the one copyright line in `THIRD_PARTY_NOTICES.md` whose holder's name matches. Copied code carries only what its license requires, in `THIRD_PARTY_NOTICES.md`: the derived files, the copyright line and the license text, with no project name, URL or commit. A file deleted or rewritten from scratch comes off the list, a restyle that keeps the source's structure or values stays on it, and an empty list deletes the file.
- The Metabase credential is encrypted with `safeStorage` in `main/auth/secret.ts` and nowhere else; a session without secret storage is an error naming the fix, never a plaintext fallback. Only the access token leaves main, through the broker.
- The broker's HTTP contract, its `/v1/` paths and the `MB_AUTH_BROKER` / `MB_AUTH_BROKER_TOKEN` names are frozen with the CLI's `core/auth-broker.ts`; the schemas both sides parse live in `contracts/broker.ts`.
- The contracts import `zod` and nothing else. The renderer compiles against the DOM lib, so a client type reaching `contracts/` drags the client's whole tree into that program; main projects what the UI needs, as `main/server-summary.ts` does.
- The channels in `testIpc` register only under `RDE_TEST_MODE`, which the headless drivers set. A packaged app answers no folder picker for its caller and mints no broker session without one.
- The renderer never touches Node. `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webviewTag: false`; `setWindowOpenHandler` denies; `will-navigate` is prevented; the CSP in `index.html` widens only with a reason in the commit. The page parses with Zod under that CSP, so `renderer/zod-setup.ts` is imported first in `main.tsx`; it turns Zod's `Function` probe off before the first schema is built and installs Zod's English messages, which the bundle would otherwise tree-shake away. Fonts are self-hosted under `src/renderer/fonts/`.
- The window's title bar is decided in `main/window.ts` alone: hidden with the traffic lights on macOS, the controls overlay elsewhere. The renderer learns which corner the operating system's buttons take from the `window.chrome` channel, never by sniffing `navigator`, and every column's top is a `WindowStrip`, the only drag region.
- The preload exposes one object, `contextBridge.exposeInMainWorld("rde", …)`, built by `createIpcBridge` from `contracts/ipc.ts`. The page never sees `ipcRenderer`. `src/renderer/bridge.ts` is the only renderer file naming `window.rde`.
- Every IPC channel, every persisted record and every provider message crossing into the app is a named zod schema under `src/contracts/`. Main and renderer import wire shapes from there and nowhere else. Every `ipcMain.handle` goes through `ipcHandler`, which parses the input and the output against the channel's schemas; a parse failure is an `IpcContractError` returned to the renderer, never a crash.
- Every `switch` over a union ends in `assertNever`. Absence is `null` or a variant, never `""`, `0` or `[]`.
- `sessions/<id>/events.jsonl` is what a session is. A command appends events, `contracts/projector.ts` folds them into the `SessionSnapshot`, and nothing else writes the read model; main and the renderer run that one fold. A line that will not parse stops the load naming its number, never a silent skip. The log's file name lives in `main/sessions/log.ts` and nowhere else.
- Git runs through `main/git/service.ts` alone, which is the only file naming the binary: reads carry `--no-optional-locks`, writes fsync the objects and refs they publish, and every diff names its own prefixes so a user's git configuration cannot change what the app parses. A checkpoint is a tree and a hidden ref under `refs/rde/checkpoints/<session>/<seq>`, captured through a private index, so the branch gains no commit and the user's staging area is untouched.
- No continuously repainting animation. Shimmer and progress run while a state is live and stop when it ends.
- Provider knowledge stays in `src/main/providers/<provider>/`. A `switch` on the provider kind outside that directory is a design bug. One directory holds that agent's wire schemas, the state machine mapping its stream onto `SessionEvent`s, the shaping of the asks a person answers, and the session; nothing outside it imports a provider SDK or names a provider protocol type. Adding a third agent is a directory and a row in `providers/registry.ts`.
- Every `SessionEvent` comes from an adapter and nothing else produces one. A mapping is a pure state machine taking its clock and event-id source from the caller, so `scripts/record-provider.ts` can capture a real session's frames and a replay test can assert the exact sequence off them. A fixture is recorded, never written by hand; a shape the box cannot record is constructed in the test and the test says so.
- The app reaches remote sync and the metadata tree through the bundled `mb` (`main/cli/runner.ts`), the path the agent takes, never through the client. The shim in `resources/rde-cli/bin/` is first on every provider's `PATH`, and the CLI's entry and `ELECTRON_RUN_AS_NODE` are named in `main/cli/paths.ts` alone.
- The app calls the Metabase client for the OAuth flow and probes only. It never names an `/api/` path; a missing endpoint is added to `packages/client` through the `add-resource-command` skill's layering.
- Tokens live in CSS (`tokens.css`, `shadcn.css`), primitives in `components/ui/` and `components/agent/`, composites in `components/`. Raw hex, arbitrary px, `text-[13px]`, a raw `<button>` or `<input>` in composite or feature code are review blockers; an arbitrary Tailwind length belongs to `components/ui/` alone, a bare `<button>`, `<input>`, `<select>` or `<textarea>` to `components/ui/` and `components/agent/` alone (a row that styles its own hit area uses `PlainButton`), and `src/architecture.test.ts` greps for all three. A text size is a step of the type scale in `tokens.css`, `text-title`, `text-body`, `text-detail` or `text-meta`, which resets Tailwind's own sizes; body is the size of anything a person reads or acts on, and meta is for metadata alone. `renderer/cn.ts` names the same steps so a merge keeps a size beside a colour.
- What the timeline shows is decided in `renderer/timeline/` and `renderer/markdown/`, never in a component: grouping, folding, the one working row, the split between finished Markdown and the text still arriving, and when following the live edge stops are pure functions with their own tests. A component renders what they return.
- The sidebar's and the side panel's widths are the `PanelLayout` in the settings record (`contracts/layout.ts`), fitted to the window by `renderer/layout.ts`. A drag moves the CSS variables `renderer/panels.ts` sets on the shell's root and commits once when the pointer lets go. A container that measures its own content carries `SETTLES_ON_RESIZE`, so a drag holds its width until it ends.
- What the Changes panel shows is decided in `renderer/changes/` the same way: the turns a view can name, what a revert returns a file to, whether commit and push can run, which one of commit, push and the pull request leads while the others wait in the panel's menu, and how git's progress output reads. A diff and a file's read-only preview render in `components/Changes/DiffViewer.tsx` alone, through its one highlighter, and every file tree, the Changes panel's and the Files tab's, in `components/Changes/FileTree.tsx` alone.
- What the Metabase panel shows is decided in `renderer/metabase/panel.ts` the same way: the head, the lines about the branch in Metabase, the content rows, which transform action is off and why, and when to read Metabase again. A capability the instance lacks is never a row of its own; it is the reason the action it stops is off.
- What the composer offers a new session is decided in `renderer/composer/choices.ts` the same way: what the session starts on, the choices, and what each chip names. `components/Composer/` renders one chip per choice and one button that sends or stops. The model is always a named model from the agent's list, never an agent default left unnamed.
- Anything the app hands the operating system, a URL for the browser or a file for the editor, goes through `main/external.ts`, and Electron's `shell` is imported in `main/index.ts` alone. Under `RDE_TEST_MODE` the opener records instead, so a driver reads back what would have opened and nothing leaves the app.
- `packages/cli/dist/` imports nothing but `node:` builtins, because the packaged app ships it under `resources/rde-cli/` with no `node_modules` beside it. `electron-updater` is imported in `main/index.ts` alone, and the updater stays off under `RDE_TEST_MODE`, so no driver reaches the release feed.
- Anything that opens a window runs under `xvfb-run -a --server-args="-screen 0 1440x900x24"`. `bun run --filter @metabase/rde-desktop smoke` is the live check; it reads `RDE_EVIDENCE_DIR` and `RDE_THEME`.
- A dependency is added with a line in the commit saying why nothing in the repo does the job. No Effect, no Redux, no Radix, no `electron-store`.

## Commands

- Use `defineMetabaseCommand({ meta, args, requires, run })` from `commands/runtime.ts`, never citty's `defineCommand`. Spread the shared flag sets from `commands/flags.ts` (`outputFlags`, `preflightFlag` for a command that reaches a server, plus `listFlags` for a list command). A new global flag must also be added to `GLOBAL_FLAG_ARGS` in `commands/global-flags.ts` or it will not survive hoisting.
- Commands call the client, never the wire. An `/api/` path literal or a `requestParsed` / `requestRaw` / `requestStream` / `paginatePages` call inside `src/commands/` belongs in `resources/`. Both rules are absolute and carry no allowlist.
- Every command declares `requires`: the `MethodKey` list of every `client.<ns>.<method>(` its body reaches (plus the methods of any helper it hands the client to), or `null` for a command that never reaches a server. The field is required, so an omission is a compile error. `commands/requires-guard.test.ts` asserts the declaration equals the calls in the body, so a list is never guessed. The preflight derives the features from `METHOD_REQUIREMENTS`, checks them through the client's own `checkFeatures` and throws its `RequirementFailure`; a command whose methods need nothing, and a `null` command, never preflight.
- Import prompts from `output/prompt.ts`, never `@clack/prompts` directly — that is where cancel becomes `AbortError`.
- Anything that can block takes `interruptSignal` explicitly: client construction, every `WaitSchedule`, any long-running fetch.

## Schemas

Every resource lives in `packages/client/src/domain/<resource-singular>.ts` and exports exactly two things:

1. **`<Resource>`** — `z.object({...}).loose()`, type aliased via `z.infer`. Loose so API additions don't break us.
2. **`<Resource>Compact`** — `<Resource>.pick({...}).strip()`. The trailing `.strip()` is mandatory: Zod 4's `.pick()` inherits a `.loose()` parent's catchall and silently passes every field through without it.

- Trim to what an agent needs: ids, names, FK targets, base/semantic types, descriptions. Drop sync flags, fingerprints, timestamps, internal plumbing.
- Pin closed enums with `z.enum([...])` where the backend enumerates the values, so a new server value fails loudly instead of passing as an untyped string.
- `.optional()` on a domain field means every supported server may omit it. Absence or a different shape on some majors is never an optional: it is a module-private `<Resource>WireV<N>` schema for that generation plus a converter to the canonical shape, selected by a feature and handed to the transport as a reader (`<resource><Endpoint>Schema(features): z.ZodType<Resource>`), and the canonical field is `nullable`, where `null` means "this server cannot say".
- Canonical is the newest supported server's shape. A converter may add fields but never collapses two distinguishable wire states into one canonical state, and it strips the wire fields it owns so the canonical JSON is identical on every server.
- Only `version/features.ts` compares a Metabase major (`major-comparison-guard.test.ts` enforces it; `profile.ts` and `tag.ts` place and parse). Everything else branches on a named feature from `FEATURE_RULES`. A feature name describes a behaviour (`transformTargetTableId`), never a version, and every version-gated rule must be non-constant across `KNOWN_RANGE.min … max + 1` (`features.test.ts`), so a rule that stops flipping is deleted with its wire variant and converter. A method may require a rule bounded by `until` only when the route itself was removed by later releases (`requirements.test.ts` pins the set); the refusal then reads `version-too-new`.
- Every resource method declares its features in `version/requirements.ts` (strictest first) and opens with `await transport.require("<ns>.<method>")`, which refuses with `CapabilityError` before any request; `requirements.test.ts` asserts the literal set equals the table. A method that reads a version-selected shape then reads `(await transport.server()).features` and parses with the reader.
- Presentation is the CLI's: the terminal binding is `<resource>View` in `packages/cli/src/output/views/<r>.ts`. Never inline a column list in a command; never put a `ColumnDef` on the client surface.
- Resource methods (`packages/client/src/resources/<r>.ts`) are the only layer naming an `/api/` path. Path params positional, then params, then options; params use Metabase's own field names verbatim with no mapping layer; transport concerns (`signal`, `timeoutMs`, `retries`) only in the trailing options; wire envelopes stay module-private; methods return domain values, and a non-paginated list returns `ListResult<T>`; every string path param goes through `encodeURIComponent`; every method carries the endpoint's description as a doc comment.
- List commands wrap items in `ListEnvelope<T>` via one of `windowList` / `windowServerPage` / `collectForOutput` (`packages/cli/src/output/window.ts`), and export the envelope schema as a named const used both as the command's `outputSchema` and by its e2e test. `has_more` reports what the walk observed — only a source that ran dry may report `false`, and a server count never overrides rows already in hand. `has_more: true` carries a `next_offset` greater than `offset`, or `null` when `--max-bytes` left no room for a single row — an empty window has nowhere to resume from, so it reports the rows that remain and offers no offset to repeat.
- The client is embeddable: no message it produces may name the CLI, an `mb` command, or a CLI flag.

## Skills

- A shipped skill under `packages/cli/skill-data/` describes the newest Metabase plainly, with no version prose. What it relies on is declared: `requires: [<FeatureName>, …]` in frontmatter for the whole skill, and `<!-- requires: a, b -->` … `<!-- /requires -->` around a passage, each marker on its own line and never inside a Markdown table. `core/skills.ts` validates both on every read; `core/skills.test.ts` pins the shipped skill-level map, so a new feature-bound skill is added there.

## Tests

- Test code is code: the type rules above apply in full.
- Tests import production schemas from source and never redeclare them, and reuse the client's helpers (`parseJson`, `pollUntil`, `isFileNotFoundError`, `errorMessage`) rather than reimplementing them.
- Assertions are full and exact: `toEqual(<full object>)` over field-by-field `toBe`; exact exit codes (`toBe(2)`, never `.not.toBe(0)`); exact error strings (`toContain("…")` / `toBe("…")`, never `toMatch(/…/i)`). When asserting an error, assert the type AND the exact message slice.
- One concept per test. No tautologies, no tests that re-encode the implementation, no fixture values used by zero assertions. Never `expect(Schema.parse(fixture)).toEqual(fixture)` — schema correctness is proven in e2e against live output.
- `vi.mock` is a last resort. Acceptable only to isolate a side-effecting dep that pollutes the host or to inject a fixture into a fully-exercised pipeline. Never to make a one-line wrapper "testable in isolation".
- Layering rules apply to production source only; `*.test.ts` may import across layers.

| Tier          | Glob                                        | Network                             | When                           |
| ------------- | ------------------------------------------- | ----------------------------------- | ------------------------------ |
| `unit`        | `packages/*/src/**/*.test.ts`               | none                                | every source change            |
| `e2e`         | `tests/e2e/**/*.e2e.test.ts`                | live Metabase                       | every new command              |
| `desktop-e2e` | `packages/desktop/scripts/**/*.e2e.test.ts` | live Metabase, a signed-in `claude` | every change to an interaction |

E2E invariants — the full contract is in `.claude/skills/add-e2e-test`:

- `runCli` is the only way to invoke the CLI. Never call `execa` / `child_process`, never `fetch` Metabase directly.
- Never hard-code an entity id or an API key. Read ids from `SEEDED`, credentials via `readBootstrap()`. A suite that needs the CLI to see a particular cached server seeds the probe cache through `tests/e2e/seed-probe.ts`; a broker is an in-process `node:http` fixture (`packages/cli/src/core/broker-fixture.ts`).
- State does not persist between tests — each opens on the restored snapshot. Capturing a snapshot is the bootstrap's alone.
- A gated suite passes a `lane` label to `requireServer(lane, {...})` / `requireOAuthServer(lane)`, so a skipped lane is reported rather than counted as passing.
- Never read or print the EE license token (`MB_PREMIUM_EMBEDDING_TOKEN`). To check whether a token-gated lane runs, test the env var for `undefined` — never its value.

## Gate

`bun install` (npm is too old). The whole gate is `bun run check` — `tsc --noEmit`, `oxlint`, `oxfmt --check`, `bun run test`, `lint:skills`, in that order, stopping at the first failure. `bun run check:fix` applies the fixing variants.

Nothing is done until `bun run check` passes. A change touching a command's behaviour isn't done until its e2e lane passes too (`bun run build && bun run e2e:up && bun run e2e:bootstrap`, then `bun run test:e2e`).

Never name the gate after an npm lifecycle hook (`prepare`, `postinstall`) — bun runs those during `bun install`.
